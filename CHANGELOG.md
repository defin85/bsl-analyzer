## [Unreleased]

### Added

- Внешние обработки и отчёты (EPF/ERF) как источник третьего вида
  (github#45): объявляются в `[source] externals` или флагом
  `--external NAME=PATH`, без настройки обнаруживаются в `src/epf/*` и
  `src/erf/*`. Внешний объект получает собственный вид
  (`ВнешняяОбработкаОбъект` / `ВнешнийОтчетОбъект`), владельца по раскладке
  выгрузки, навигацию по платформенным методам, автодополнение и раздел
  `external:<имя>` в базовой линии диагностик; проекты без EPF отпечатка не
  меняют.

- MCP-сервер умеет вторую ветку исполнения на расширении протокола
  `io.modelcontextprotocol/tasks`. Чтения резидентной базы анализа —
  `metadata` (`info`/`tree`/`object`), `symbol_info`, `references`,
  `diagnostics` в действиях `file` и `workspace` — отвечают клиенту,
  объявившему расширение, долговечным хэндлом вместо конверта «индекс
  строится»: хэндл переживает обрыв соединения, опрашивается `tasks/get`,
  снимается `tasks/cancel` и имеет собственный срок, по которому работа
  прекращается, а не бросается. Ветка выключена по умолчанию и включается
  переменной `BSL_MCP_TASKS`; клиент, расширение не объявивший, не видит
  ни одного изменения. Политика запуска сборок индекса не меняется.
  Подробности — `docs/mcp/TASKS.md`.

- `bsl-analyzer mcp serve --mode http` принимает настройки привязки файлом:
  `--config <файл.toml>` с полями верхнего уровня `host`, `port` и массивом
  `allowed_hosts`. Обязателен только `port`: опущенный `host` привязывает
  loopback, опущенный `allowed_hosts` оставляет встроенные локальные имена —
  ровно как у отдельных флагов. Смешивать `--config` с `--host`, `--port` и
  `--allowed_hosts` нельзя: настройки берутся целиком из одного источника.
  Правки параметров у запуска из планировщика больше не требуют правки
  командной строки.

- `textDocument/foldingRange` отдаёт складки `kind: "comment"` для серий строк
  `//`. Шапка метода по стандарту 1С сворачивается целиком: пустая строка `//`
  внутри шапки серию не разрывает, пустая строка и строка кода — разрывают,
  складка кончается на последней строке комментария и не захватывает объявление
  под ней, одиночная строка не сворачивается, а комментарий на строке с кодом в
  складку не входит. Комментарий определяется по разбору, а не поиском `//` в
  тексте, поэтому `//` внутри строкового литерала складки не даёт.
- Правила серии комментариев собраны одним примитивом `syntax::comment_runs`;
  диагностика `CommentedCode` переведена на него, собственной группировки
  комментариев у неё больше нет.

- Поиск по имени сведён к одному словарю на весь продукт. Четыре независимые
  реализации («кто так называется») заменены одним запросом в слое `ide`, который
  складывает пять уже существующих источников — таблицу модулей, перечень
  метаданных, платформу, экспортные члены модулей и узлы графа. Нового индекса и
  нового инструмента не появилось.
  - `graph action=resolve` вынесен из-за гейта готовности графа: платформенный
    член находится без единого индекса, объект конфигурации и общий модуль — как
    только готов резидент, поэтому ответ приходит и на несобранном графе.
    Ленивый запуск сборки при этом сохранён.
  - У каждого кандидата теперь блок `address`, и каждый его ключ принимается тем
    инструментом, который он называет: `symbol` — параметром `symbol` у
    `symbol_info`, `graph_id` — действием `graph node`, `syntax_help` —
    инструментом `syntax_help`, `location` — парой `(root_id, path)` у `outline`
    и `diagnostics file`. Ключ, который принят не будет, не публикуется вовсе.
    Прежнее поле `id` сохранено, но только там, где равно `address.graph_id`: до
    этого оно было у всех кандидатов и вело в никуда.
  - Массив `providers` называет каждый источник и его состояние (`answered`,
    `not_ready`, `not_asked`, `unavailable`, `failed`), поэтому пустой список
    больше не выдаётся за доказанный ноль: доказанный ноль — это пустой список
    при всех источниках в `answered`.
  - `total_exact` отличает точный счёт от оценки: если источник упёрся в
    собственный предел, отброшенное свести с чужим было нечем.
  - `symbol_info` при промахе по неточному имени отдаёт кандидатов из того же
    словаря. Раньше это была проекция графа, из-за чего без графа список был
    пуст, а платформенный член не находился никогда.
  - LSP `workspace/symbol` отвечает из того же словаря и начал отдавать объекты
    конфигурации. Собственная реализация обхода `item_tree` удалена.
  - Одна сущность приходит одним кандидатом, даже когда её знают несколько
    источников: узел графа и запись резидента дают одну строку, где есть и
    `location`, и `graph_id`. Сводятся они по файлу, который граф называет сам,
    поэтому одноимённые сущности в разных файлах остаются разными ответами:
    модуль конфигурации и одноимённый модуль расширения, экспортный метод и его
    закрытый тёзка в соседнем модуле.
  - Это работает и для объектов метаданных: граф записывает файл объекта в свой
    узел, поэтому справочник, документ, регистр, роль и подсистема приходят одной
    строкой с XML в `location` и `mdo/…` в `graph_id`, а не двумя — с местом без
    идентификатора и с идентификатором без места. У объекта, дополненного
    расширением, `graph_id` привязан к базовой конфигурации; кандидат расширения
    остаётся отдельным ответом со своим местом. Общий модуль, перечисленный в
    составе подсистемы, приходит категорией `common_module` и с
    `graph_id = module/common/…`.
  - Схема графа — `18`: узлы объектов получили поле файла, поэтому кеш прошлой
    версии перестраивается. Ничего в рабочей области при этом не меняется, и без
    смены версии устаревший кеш продолжал бы отвечать по-старому.
  - Контракт MCP — `1.9` (добавлены поля и вид карточки, ничего не удалено и не
    переименовано), схема действий `graph` — `32`. Четыре новых закрытых словаря
    описаны в `docs/mcp/TOOLS_AND_EXTENSION.md`.
- `syntax_help` отвечает и о свойствах платформы — как о свойстве типа
  (`Тип.Свойство`), так и о свойстве глобального контекста (`Справочники`,
  `Документы`, `ФоновыеЗадания`). Прежде при заданном типе он искал только в
  таблице методов, поэтому ни одно свойство через него не открывалось.
  `structuredContent` получил вид `property`.

### Fixed

- Подсветка синтаксиса больше не теряет инструкции препроцессора расширений
  (github#47). `SyntaxKind::is_preprocessor` перечислял шесть инструкций из
  десяти, поэтому `#Вставка`, `#КонецВставки`, `#Удаление` и `#КонецУдаления`
  не попадали ни в один предикат вида: в одном и том же файле расширения
  `#Область` и `#Если` подсвечивались директивами препроцессора, а эти четыре —
  никак. Разряд закрыт, и его полноту теперь держит перебор всех видов
  `SyntaxKind`, а не перечень представителей.
- MCP: промах по имени, пришедший сразу после чужой сверки с диском, больше не
  возвращается клиенту окончательным (github#37). Люк «промах → форс сверки →
  повторное чтение» защищён полом в 250 мс, и форс, пришедший внутри этого пола,
  раньше проглатывался молча: повторное чтение шло по тому же слепому резиденту,
  и `references`/`symbol_info`/`metadata object` отвечали `not_found` про имя,
  лежащее на диске. В простое такое окно открывает сам сервер — сторож
  `reconcile_tick` перештамповывает кэш скана по своему расписанию, поэтому
  вызов, попавший в пол после его тика, промахивался без единого обхода.
  Теперь отказ пола сообщается вызывающему временем, которое пол ещё должен;
  политика повтора выжидает ровно его (не больше самого пола) и просит форс
  заново. Частота обходов не изменилась: по-прежнему не чаще одного на пол.
  Отмена, пришедшая во время ожидания, повтор снимает.
- `$/cancelRequest` доходит до многофайловых обработчиков LSP: токен отмены
  Salsa больше не стирается на границе tracked-функции, и обход тысячи модулей
  в поиске ссылок прерывается на границе файла (github#41).
- MCP: `search_code`, `find_docs` и `search_docs` отменяются per-request
  токеном, включая ожидание замка движка и HTTP эмбеддинга (github#44).

- MCP-демон профиля `workspace` больше не расходует процессор в простое, когда
  каталог кеша лежит внутри наблюдаемого дерева (расположение по умолчанию
  `<source-dir>/.build`). Записи, которые сервер делает в собственный кеш,
  возвращались к нему же как изменения воркспейса: наблюдатель их записывал,
  поколение накопителя росло, потребитель просыпался «на работу», при
  применении перештамповывал лиз писателя — и порождал следующее событие. На
  стенде из 40 общих модулей демон занимал ядро целиком и давал 34 158 файловых
  событий за 3 секунды простоя; стало 0.
  - каталог кеша исключён из области наблюдения. Исключение задаётся при
    создании наблюдателя и переармированием на новый набор корней не снимается;
    путь сверяется в обоих написаниях — заданном и каноническом, — потому что
    события приходят под тем, которым наблюдатель был вооружён.
  - проход потребителя, которому нечего применять, больше не берёт фенс лиза и
    не перештамповывает его. Устаревание плана при этом по-прежнему проверяется:
    пустой план мог стать пустым именно из-за смены набора корней.
  - ожидание изменений идёт по предикату до дедлайна, а не по одиночному
    пробуждению: условная переменная вправе проснуться ложно, и такое
    пробуждение стоило потребителю полного прохода.
  - перештамповка лиза внутри удерживаемого фенса ограничена одной записью в
    секунду. Проверка «лиз отобран» при этом не откладывается ни на такт.
- `mcp serve --profile workspace` отказывается стартовать, если `--cache-dir`
  содержит любой сканируемый корень (включая корень расширения): такой каталог
  исключил бы этот корень из наблюдения, и сервер молча перестал бы следить за
  деревом, которое обслуживает.
  Вопрос «лежит ли путь в корне или в дыре внутри него» задаётся одному типу
  (`project_model::PathScope`) наблюдателем, обходом и этой проверкой. Прежде у
  правила было три независимых реализации, и они успели разойтись дважды. Отсюда
  два исправления поведения:
  - корень, заданный в конфигурации через `..` (`root = "../elsewhere/sources"`),
    больше не обходит ни отказ при старте, ни отсечение при обходе: путь такого
    корня не разрешался, а сравнение шло лексически, и каталог кеша над ним
    возвращался в индекс как исходники;
  - каталог кеша перестал входить в тождество набора корней. Сравнение целого
    набора читается в две стороны — «корни не менялись, короткий путь» и «план
    сделан не для этих корней, отбросить», — поэтому разница в одном лишь
    расположении кеша и вызывала лишний полный переход корней, и отбрасывала
    годный план перехода.

- Ранжирование словаря: точное совпадение с хвостовым сегментом durable-id
  (`name`) снова сильнее простого префикса. Тир `prefix`, добавленный ради
  `workspace/symbol`, встал между `case_insensitive` и `name` и опускал точные
  попадания графа ниже более длинных имён резидента, а при узком пределе
  вытеснял их из ответа вовсе.
- Общий модуль без читаемого тела (защищаемый модуль: XML есть, `.bsl` нет)
  больше не публикует `symbol`. `symbol_info` резолвит общие модули через
  таблицу модулей, построенную по путям, и такого модуля в ней нет — ключ
  отвечал пустотой. Найти и открыть его по месту по-прежнему можно.
- Провалившаяся сборка резидентной базы называется в `providers` как `failed`, а
  профиль без рабочей области — как `unavailable`. Прежде оба состояния
  схлопывались в `not_ready`, то есть звали ждать сборку, которая уже упала или
  не начнётся никогда.
- Пустой запрос к словарю называет все пять источников как `not_asked`. Прежде
  ответ приходил с пустым `providers` и полным конвертом — ровно та форма,
  которую `providers` и заведён исключать.
- `workspace/symbol` больше не роняет весь запрос, когда файл одного кандидата
  разошёлся с диском или стал нечитаем: такой кандидат пропускается с записью в
  журнал, как это уже делали `workspace/diagnostics` и пакетный обход. Поиск по
  имени возвращает файлы, которых никто не называл, и XML метаданных
  переписывается конфигуратором и git чаще любого другого файла.
- Таблица экспортных членов модулей (`module_members`, бывш. `workspace_symbols`
  в `hir-def`) ключевалась именем модуля, выведенным из имени файла, из-за чего
  все `ObjectModule.bsl` конфигурации схлопывались в один и методы почти всех
  объектных и менеджерных модулей терялись. Ключ — `FileId`. Заодно таблица
  получила экспортные модульные переменные, которых в ней не было вовсе.

- MCP: инструмент `outline` — карта одного `.bsl`-файла: дерево `#Область`,
  процедуры, функции и модульные переменные с экспортом, директивами компиляции,
  параметрами (`Знач`, три состояния умолчания) и диапазонами. Тел методов не
  отдаёт. Вход — `path` (+ `root_id`, как в хитах `search`), режим `full` или
  `regions` (только скелет областей). Отвечает от одного разбора названного файла:
  не строит ни резидентную базу, ни граф, ни индекс, поэтому конверта `loading`
  у него нет и ответ одинаков на холодной и прогретой рабочей области. Усечение
  бюджетом отбрасывает целые узлы с хвоста документа и помечается `truncated`
  с `budget_hint`; в конверте свежести появилось значение `source: "file-parse"`
  с `null` вместо чужих ревизии и отпечатка топологии.
- MCP: единый location contract v1 в ответах `search`, `symbol_info`, `diagnostics`
  и `graph` — объект места с парой `(root_id, path)`, двумя диапазонами (0-based,
  конец исключающий, колонки в кодовых единицах UTF-16 с явным `position_encoding`)
  и конверт `freshness` с отпечатком топологии и машиночитаемой полнотой. Старые
  поля сохранены без изменения значений и помечены устаревшими; подробности в
  `docs/mcp/LOCATION_CONTRACT.md`.
- `ide`: карта файла несёт объявление, а не только имя — признак экспорта,
  директивы компиляции и параметры (имя, `Знач`, значение по умолчанию), причём
  «умолчание есть, а текст выражения нечитаем» — отдельное состояние, а не
  «параметр обязателен». Добавлен режим `OutlineMode::RegionsOnly`
  (`Analysis::file_outline`) — скелет областей без их содержимого.

### Changed

- Метод стал единицей пересчёта диагностик (github#113). Лоуэринг, вывод
  типов, dataflow, диагностики тела и строчные проверки запоминаются по
  устойчивому тождеству метода, а не по файлу; правка внутри метода
  переразбирает только его. На модуле ERP в 107 тысяч строк первый ответ
  диагностики после правки тела сократился с 7.3 с до 0.35 с, после правки
  сигнатуры — с 7.5 с до 0.40 с, после вставки метода — до 0.56 с. Множество
  диагностик пакетного `analyze` не изменилось, кроме одного случая:
  `CommentedCode` больше не поднимается на строках `//|` многострочного
  литерала запроса внутри `#Вставка` — там парсер не строит узел литерала,
  и старое правило принимало текст строки за комментарий.

- **Ломающее изменение.** Флаг разрешённых имён у `mcp serve --mode http`
  переименован из `--allowed-host` в `--allowed_hosts` и принимает несколько
  значений одним флагом (`--allowed_hosts localhost 127.0.0.1 ::1 mcp.local`)
  вместо повторения флага на каждое имя. Прежнее имя не принимается: запуски
  с `--allowed-host`, написанные для v0.2.71 и старше, нужно переписать.

- `CommentedCode` больше не считает закомментированным кодом текст внутри
  закрытого многострочного строкового литерала: строки запроса, начинающиеся с
  `//`, лексер отдаёт токенами комментария, и раньше они попадали в находку. На
  стенде из 21 114 модулей это снимает 20 срабатываний, ни одного нового не
  появляется.

- LSP `documentSymbol`: область, объявленная внутри тела метода, в карту больше
  не попадает — карта описывает структуру модуля, а не тела; порядок узлов на
  каждом уровне теперь совпадает с порядком объявления в файле (прежде области
  шли перед всем остальным независимо от места в тексте).

### Fixed

- LSP `documentSymbol`: символ, диапазон которого не проецируется на открытый
  буфер (снимок анализа разошёлся с документом), больше не выбрасывался молча
  вместе со всеми потомками — запрос отвечает отказом и пишет предупреждение
  с URI. Урезанная карта неотличима от файла, в котором этих методов нет.

### Removed

- Removed the deprecated `--streaming` CLI flag and the legacy streaming
  analysis pipeline (`ide::streaming` / `ide_db::streaming`). Salsa is now
  the only production analysis path for both LSP and CLI batch analysis.
